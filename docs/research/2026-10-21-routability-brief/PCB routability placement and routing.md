# Charge the winners, size channels per edge

**BLUF.** The 203/235 plateau has two independent causes with two independent, cheap fixes. The 32 intra-block opens are a *supply* failure no router can repair: with w = s = 0.2 mm a same-layer track needs a 0.6 mm copper-to-copper gap (s + w + s), so a 0.26 mm courtyard gap admits zero tracks. The fix belongs in agent-ee as a per-edge, net-aware gap `G_req(edge) = s + ceil(n_edge / L_eff)·(w + s)` in place of the global 0.6 mm the fixed geometry cannot honour; OpenROAD's pin-aware macro halos already work this way ([clusterEngine.cpp](https://raw.githubusercontent.com/The-OpenROAD-Project/OpenROAD/master/src/mpl/src/clusterEngine.cpp)). The long-bus opens plateau because kicad-route, like Freerouting, carries no persistent per-cell price: a deterministic router without history converges to the same fixed point however long it runs, and reordering nets only re-samples the same landscape, which Abel measured in 1971 ([Abel 1971](https://www.ideals.illinois.edu/items/100649)) and PathFinder fixed in 1995 with an additive history term ([McMurchie & Ebeling](https://www.esa.informatik.tu-darmstadt.de/archive/twiki/pub/Lectures/AlgorithmenImChipEntwurfDe/router-pathfinder.pdf)). Every router that converges rather than plateaus (VPR, FastRoute, NTHU-Route, TritonRoute, Dr. CU) shares two additions, per-resource history and overuse-restricted reroute, and differs only in constants; both retrofit onto KRT's A* as a cost term plus an outer loop seeded from the frontier-blocking data KRT already computes. A static escape pre-pass and a PCBWorld-style metric set complete the programme. **Scope interpretation:** the truncated "Do not propose" is read as "do not propose replacing or rewriting the toolchain" (no commercial router, no Rust/C++ rewrite, no RL placer); everything below is an incremental change to agent-ee, kicad-route, or how they drive Freerouting and KiCad DRC.

Notation: w = track width (0.2 mm), s = clearance (0.2 mm), P = w + s = 0.4 mm pitch, G = copper-free gap between two blocks on one layer, n_edge = signal nets that must cross a block edge, L_eff = signal layers actually free in that corridor (≤ 2). DERIVED marks formulas inferred from a cited definition; UNVERIFIED marks claims whose primary source could not be read.

## 1. Routability-driven placement: the estimators are cheap, but our failure is supply, not demand

RUDY (Spindler & Johannes, "Fast and accurate routing demand estimation for efficient routability-driven placement," DATE 2007, DOI 10.1109/DATE.2007.364463) deposits, per net e with bounding box w_e × h_e, uniform density ∝ (1/w_e + 1/h_e) inside the box; directionally, RUDY_h(bin) = Σ_e R(bin, bbox_e)/h_e and RUDY_v(bin) = Σ_e R(bin, bbox_e)/w_e with R the overlap area ([RoutePlacer App. E](https://arxiv.org/pdf/2406.02651); [Liu et al. DATE 2021](https://past.date-conference.com/proceedings-archive/2021/pdf/1290.pdf)). OpenROAD's `Rudy::visitNetTiles` in `src/grt/src/Rudy.cpp` is the executable definition: `net_congestion = hpwl·wire_width/net_area` scaled per tile by `intersect_area/tile_area`, `wire_width` = 1.25× the harmonic mean of layer pitches ([Rudy.cpp](https://raw.githubusercontent.com/The-OpenROAD-Project/OpenROAD/master/src/grt/src/Rudy.cpp)). RISA (Cheng, ICCAD 1994) is the same box model with a pin-count weight (1.0 at ≤3 pins, 1.45 at 10, 2.79 at 50) and, crucially, a *supply* model in which cells reduce a region's tracks by porosity and two-layer mega cells block fully; cost Σ[max(D − t·S, 0)]² enters an annealing objective ([RISA](https://cecs.uci.edu/~papers/compendium94-03/papers/1994/iccad94/pdffiles/10d_3.pdf)). Brenner & Rohe's two-bend probabilistic model (ISPD 2002) sits between these box models and a real global router in both cost and fidelity ([Brenner & Rohe](https://websrv.cecs.uci.edu/~papers/compendium94-03/papers/2002/ispd02/pdffiles/01_1.pdf)). Pin-density windows (CRISP's >1 pin per minimum cell; the DATE 2022 SMT analog placer's hard cap Σ|P(v_i)|·b_ij ≤ λ_th per window) are the cheapest and target "too many pads in one window" directly ([CRISP](https://web.eecs.umich.edu/~imarkov/pubs/conf/iccad09-crisp.pdf); [Chen et al. DATE 2022](https://past.date-conference.com/proceedings-archive/2022/pdf/0189.pdf)). All are sub-millisecond in NumPy at 235 nets.

Integration is uniform: per-tile congestion → per-cell area inflation `ratio = clamp((cong/threshold)^k, 1, r_max)`, k ∈ {2, 2.33, 2.5}, r_max ∈ {2.5, 3}, width and height scaled by sqrt, ~10% of whitespace per pass, re-spread, iterate. OpenROAD gpl documents `inflation_ratio_coef` 2, `max_inflation_ratio` 3, `min_congestion_for_inflation` 0.95, stop after 3 non-improving rounds ([routeBase.cpp](https://raw.githubusercontent.com/The-OpenROAD-Project/OpenROAD/master/src/gpl/src/routeBase.cpp); [gpl README](https://openroad.readthedocs.io/en/latest/main/src/gpl/README.html)); RePlAce uses γ = 2.33, cap 2.5 ([RePlAce TCAD](https://vlsicad.ucsd.edu/Publications/Journals/j126.pdf)). What a packer can borrow are the techniques that act on *legal* placements: CRISP's {inflate, spread, legalize, re-route} loop with `width(c,i) = max(width(c,i−1)+1, ceil((1+0.2·T)·numPins(c)))`, ≤1% of core area per iteration, DRC −79% on industrial designs ([CRISP](https://web.eecs.umich.edu/~imarkov/pubs/conf/iccad09-crisp.pdf)); SimPLR's Ca-DP rule (no swap into a congested gcell unless the mover has fewer pins) ([SimPLR](https://web.eecs.umich.edu/~imarkov/pubs/conf/iccad11-simplr.pdf)); and POLAR 2.0's legalization window test Σ supply ≥ α·Σ demand ([POLAR 2.0](https://home.engineering.iastate.edu/cnchu/pubs/c74.pdf)). Density penalties and differentiable GNN estimators (DREAMPlace-Cong, RoutePlacer) do not transfer: a packer has no density field and no gradient.

PCB-specific placers of 2018–2026 almost never use RUDY. NS-Place maximises an SVM margin between nets' pin convex hulls, validates with Freerouting + KiCad DRC, cuts DRV+unrouted 81% versus manual but loses on a board with ~20% whitespace ([arXiv 2210.14259](https://arxiv.org/pdf/2210.14259)); Cypress (ISPD 2025, Apache-2.0) adds two-sided electrostatic density and a Bézier net-crossing term and scores routability as Freerouting's routed-pin-pair fraction ([Cypress](https://github.com/NVlabs/Cypress)); HiePlace (TCAD 2026) counts crossings ([HiePlace](https://www.cse.cuhk.edu.hk/~byu/papers/J156-TCAD2026-HiePlace.pdf)). None models through-hole pins as all-layer blockages or plane layers; the one open tool that does is KiCad's `AR_AUTOPLACER` (TH footprints tested on both matrix layers, graded keepout `GridRouting·PadCount/AR_GAIN`, AR_GAIN = 16, no congestion term) ([ar_autoplacer.cpp](https://raw.githubusercontent.com/KiCad/kicad-source-mirror/master/pcbnew/autorouter/ar_autoplacer.cpp)). The closest published analogue to our symptom is Jokela's pyplacer-vs-Quilter study on a 161-net 4-layer board: 93.8% routed against 99.4%, failures at connector-edge congestion, Quilter "leaving gaps for routes to fan out" ([tinycomputers.io](https://tinycomputers.io/posts/what-a-commercial-pcb-placer-does-that-my-open-source-one-cant.html)). The decisive inference: a resistor-to-resistor net's bounding box is tiny and its RUDY demand lands in a region whose supply is zero; RISA's supply model, KiCad's pad-count keepout and pin-density windows detect that, RUDY alone does not. With 2 signal layers and 235 nets, the PCB papers' crossing proxies also fit our regime better than a many-layer averaging estimator.

**What this would mean for our tools.** Ranked: (1) a net-aware minimum gap in the intra-block packer, `gap ≥ s + k·P` whenever k nets must pass between two adjacent courtyards (k = 0 keeps 0.26 mm) — RISA's supply model in one dimension, tens of lines, removes the 32-net class; (2) score candidate block slots by a pin-density window and an exact O(nets²) 2-pin crossing count, rejecting a slot whose surrounding supply < α·demand before backjumping (POLAR's test); (3) a CRISP-style outer loop that reads open nets per tile from a kicad-route run, inflates those courtyards by `clamp((cong/0.95)^2, 1, 3)`, and re-packs — higher payoff for buses, but each iteration costs a router run.

## 2. Channel reservation: vendors give no formula, the per-edge pin-count rules do

No vendor source gives a halo width; Cadence staff say channel size "is going to depend on your design," and a poster's "nets crossing / pins facing × M2 pitch" was not endorsed (UNVERIFIED) ([Cadence forum](https://community.cadence.com/cadence_technology_forums/f/digital-implementation/19132/how-to-fix-channel-gap)). Two published closed forms exist, both per side. NCKU's expansion macro (Lin, Yu, Chang, ASP-DAC 2017, DOI 10.1109/ASPDAC.2017.7858362): `e(i) ≈ γ·N_p^i·w_avg + s_avg + s_DRC`, N_p^i = pins on side i; overflow on their circuit 4 fell 3225 → 293 (commercial tool 1071); the slide text is partly garbled so the exact s_avg placement is uncertain ([ASP-DAC 2017 slides](https://www.aspdac.com/aspdac2017/archive/pdf/5C-1_add_file.pdf)). Ou, Chien & Chang DAC 2013, restated by Basso et al. because the DAC text was unretrievable: `λ_{i,[h,v]} = ζ + |p_{i,[h,v]}|·(max spacing + max width)`, applied symmetrically because exit direction is unknown; on a two-layer H/V grid dead space rose 37% → 57% but routing failures fell ([Basso et al. arXiv 2510.15387](https://arxiv.org/html/2510.15387v1)). OpenROAD's Hier-RTLMP mechanises the same idea: `-min_channel_size {w h}` (the deprecated `-halo_width` = channel/2), and with `-pin_aware_channels`, `buildPinAwareHalo()` assigns each non-supply pin to its nearest macro side; only pin-bearing sides get the channel halo, pinless sides keep LEF `minimum_spacing` ([mpl README](https://openroad.readthedocs.io/en/latest/main/src/mpl/README.html); [clusterEngine.cpp](https://raw.githubusercontent.com/The-OpenROAD-Project/OpenROAD/master/src/mpl/src/clusterEngine.cpp)). That is the per-edge rule the global 0.6 mm failed to be.

Width comes from channel density: S(col) = nets with a pin in the column or pins on both sides; d = max |S(col)| is a lower bound on tracks, exact without vertical constraints, exceeded when nets must cross inside a two-layer H/V channel ([Lienig & Scheible ch. 6](https://ifte.de/books/eda/chap6.pdf); [KFUPM notes](https://faculty.kfupm.edu.sa/COE/sadiq/COE_572_T061/COE572/slides/chapter7.slides.ps.pdf)). DERIVED single-layer width: `W_channel ≥ s + d·w + (d−1)·s + s = d·(w+s) + s = 0.4d + 0.2 mm`: n = 1 → 0.6 mm, 2 → 1.0, 3 → 1.4, 4 → 1.8. The inverse mirrors OpenROAD's `computeGCellCapacity` track count, `c = floor((G − s)/P)`: 0.26 mm → 0, 0.6 → 1, 1.0 → 2, 1.4 → 3 ([GlobalRouter.cpp](https://raw.githubusercontent.com/The-OpenROAD-Project/OpenROAD/master/src/grt/src/GlobalRouter.cpp)). OpenROAD also discards a single leftover track beside a macro (`if resources_left == 1: end_point += track_space`); a 0.6 mm corridor has zero slack for via drills or teardrops. Courtyards are not a routing knob: KLC F5.3 clearances are assembly clearances ([KLC F5.3](https://klc.kicad.org/footprint/f5/f5.3/)), and for 0402s "copper clearances limit placement more than the suggested courtyards do" ([KiCad forum](https://forum.kicad.info/t/space-for-courtyard-for-rc-filter-and-assembly/52164)).

DERIVED per-edge rule: `G_req(edge) = s + ceil(n_edge / L_eff(edge))·P`. With L_eff = 1: n = 0 → courtyard minimum, 1 → 0.6, 2 → 1.0, 3 → 1.4; with L_eff = 2: n = 2 → 0.6, n = 3–4 → 1.0. L_eff is at most 2 and usually less, since F.Cu beside a block is consumed by its own pads and B.Cu by its fanout vias; count a plane layer as +1 only for one short jumper per corridor, remembering each jumper's via pair removes ≈ via_dia + 2s of width on both outer layers (our inference; no source quantifies it). The fixed corridors (connector 0.36 mm from holes, IMU ring, RF 0.16 mm) are legitimately n = 0 or pre-routed; model them the OpenROAD way as obstructions with c = 0 that push demand to other edges. The premise that MAGICAL/ALIGN reserve routing space by formula is UNVERIFIED and contradicted by the retrievable papers: MAGICAL's placer optimises WL/area/symmetry with non-overlap only and checks routability afterward; ALIGN handles routing room via router blockages ([MAGICAL D&T 2021](https://par.nsf.gov/servlets/purl/10356330); [ALIGN ISPD 2023](https://ispd.cc/ispd2026/slides/2023/protected/ISPD2023-Session-05/5_4_SachinSapatnekar.pdf)).

**What this would mean for our tools.** (1) Replace the global gap with `G_req(edge)` from the netlist: n_edge = nets with pins inside and outside the block, assigned to the edge facing the external partner (HPWL direction), plus pass-through nets between other blocks; a per-edge constraint in the existing first-fit checker, compatible with the fixed geometry because n = 0 edges keep their DRC minimum. (2) Model RF/IMU/mounting corridors as c = 0 obstructions. (3) Count ≤ 1 track as 0 unless pre-planned. All low cost; (1) carries nearly all the payoff.

## 3. Congestion-aware routing: history is the convergence mechanism, ordering is a tiebreak

PathFinder's cost is `c_n = (b_n + h_n)·p_n`; the 1995 paper gives no update rule beyond h_n growing "slightly" each shared iteration and p_n "gradually increased" ([McMurchie & Ebeling](https://www.esa.informatik.tu-darmstadt.de/archive/twiki/pub/Lectures/AlgorithmenImChipEntwurfDe/router-pathfinder.pdf)). VPR's production form, verified in source: `cost = base_cost·acc_cost·pres_cost`, `pres_cost = 1 + pres_fac·(overuse + 1)` when `occ − capacity ≥ 0` (a node at capacity already pays), and after each iteration `acc_cost += overuse·acc_fac` on overused nodes ([route_common.h](https://github.com/verilog-to-routing/vtr-verilog-to-routing/blob/master/vpr/src/route/route_common.h); [route_common.cpp](https://github.com/verilog-to-routing/vtr-verilog-to-routing/blob/master/vpr/src/route/route_common.cpp)). Schedule: `first_iter_pres_fac` 0 (overlap allowed), `initial_pres_fac` 0.5, `pres_fac_mult` 1.3, `max_pres_fac` 1000, `acc_fac` 1, 50 iterations, `bb_factor` 3, `astar_fac` 1.2, bounding boxes doubled every 5 conflicted iterations, only nets with an overused node rerouted ([route.cpp](https://github.com/verilog-to-routing/vtr-verilog-to-routing/blob/master/vpr/src/route/route.cpp); [VPR docs](https://docs.verilogtorouting.org/en/latest/vpr/command_line_usage/)). The TU Darmstadt worked example shows why both knobs are needed: with present cost only an unblocked net never moves and the example never becomes overlap-free; with history the contested node is priced up until one net leaves ([ace08 slides](https://www.esa.informatik.tu-darmstadt.de/archive/twiki/pub/Lectures/AlgorithmenImChipEntwurf10De/ace08.pdf)). Abel's 1971 study of five orderings on 38 boards found ordering "has little if any effect," no ordering won everywhere, and tie-break noise moved results as much as the method ([Abel 1971](https://www.ideals.illinois.edu/items/100649)); that is our 59–64-open reordering rounds. KRT's docs claim the opposite ([net-ordering.md](https://raw.githubusercontent.com/drandyhaas/KiCadRoutingTools/main/docs/net-ordering.md)); both hold: MPS lifts first-pass completion, then the residual failures are fixed by which cells early nets consumed.

The ASIC global routers share one shape: cheap iteration 0, then each iteration *steepens* the present cost and *accumulates* history on overflowed edges, rerouting only nets touching them. OpenROAD's FastRoute 4.1 fork tabulates `cost = cost_height/(exp((capacity − index)·logistic_coef) + 1) + 1` plus `cost_height/slope·(index − capacity)` past capacity, with index = `usage + L·last_usage` (history) ([maze.cpp](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/grt/src/fastroute/src/maze.cpp)); `updateCongestionHistory` does `last_usage += overflow` on overflowed edges, `×0.9` elsewhere; `COSHEIGHT = 4`, `CSTEP = 2/2/5`; rip-up at `usage ≥ cap + 1`; nets re-sorted by overflow only every third iteration ([graph2d.cpp](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/grt/src/fastroute/src/graph2d.cpp); [FastRoute.cpp](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/grt/src/fastroute/src/FastRoute.cpp); [utility.cpp](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/grt/src/fastroute/src/utility.cpp)). NTHU-Route uses `cost = 1 + h_e·p_e`, h_e += 1 while overflowed, `p_g = ((d_g + 1)/c_g)^5`; its 1.0 and 2.0 releases used *opposite* bounding-box orders and both won contests ([NTHU-Route 2.0](https://websrv.cecs.uci.edu/~papers/iccad08/PDFs/Papers/05A.1.pdf)). CUGR doubles its logistic slope per iteration and reroutes only violating nets; its `histWireUsageMap` is populated and faded but, in the snapshot read, never consumed by `getWireShortCost`, so its history is effectively unused ([Router.cpp](https://github.com/cuhk-eda/cu-gr/blob/master/src/multi_net/Router.cpp); [GrRouteGrid.cpp](https://github.com/cuhk-eda/cu-gr/blob/master/src/gr_db/GrRouteGrid.cpp)); Dr. CU's does feed cost ([RouteGrid.cpp](https://github.com/cuhk-eda/dr-cu/blob/master/src/db/RouteGrid.cpp)). SPRoute reaches zero overflow on bigblue1 at iteration 15–20 ([SPRoute](https://csl.yale.edu/~rajit/ps/sproute.pdf)); SPRoute 2.0 pre-reduces capacity in RUDY/pin-density hotspots ("soft capacity"), cutting shorts 43% versus CUGR ([SPRoute 2.0](https://www.aspdac.com/aspdac2022/taoka/pdf/8B-2.pdf)). NCTU-GR 2.0's cost function is UNVERIFIED (binary-only, paywalled).

TritonRoute is the closest open analogue to a capacity-1 detailed grid. `strategy()` in `FlexDR.cpp` is a 65-entry schedule: clip size 7 with shifting offsets, `workerDRCCost` (present conflict) 1→2→4→8→16→32→64× `ROUTESHAPECOST` (8), `workerMarkerCost` (history) 1→16× `MARKERCOST` (32), marker decay 0.95→0.99→0.999, `mazeEndIter` 3→8→16→32→64, interleaved `RipUpMode::ALL` resets with smaller clips ([FlexDR.cpp](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/drt/src/dr/FlexDR.cpp)). History is marker-based: each DRC marker bloats to cover ≥2 grid nodes along the offending segment and adds +10 to their `markerCost`, decayed per reroute; only aggressor nets named by markers are ripped, queued fewer-reroutes-first ([FlexGridGraph.h](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/drt/src/dr/FlexGridGraph.h); [FlexDR_init.cpp](https://github.com/The-OpenROAD-Project/OpenROAD/blob/master/src/drt/src/dr/FlexDR_init.cpp)) ([TritonRoute-WXL](https://vlsicad.ucsd.edu/Publications/Journals/j136.pdf)). Freerouting has no per-cell history: `ripupCosts = startRipupCosts(100)·ripupPassNo` is a per-pass scalar, per-obstacle cost is `ripupCosts·halfwidth/detour` with random noise `detour *= 0.5 + r²` from pass 4, added to the Dijkstra path value ([AutorouteConnectionRouter.java](https://github.com/freerouting/freerouting/blob/master/src/main/java/app/freerouting/autoroute/pipeline/AutorouteConnectionRouter.java); [MazeRipupResolver.java](https://github.com/freerouting/freerouting/blob/master/src/main/java/app/freerouting/autoroute/maze/MazeRipupResolver.java)), and after two stagnant passes it deterministically shuffles net order ([AutoroutePassRunner.java](https://github.com/freerouting/freerouting/blob/master/src/main/java/app/freerouting/autoroute/pipeline/AutoroutePassRunner.java)). That is noise, not pressure, and it predicts "identical result at 2× budget." KRT 0.23.1's A* cost is `g + move_cost + turn_cost + proximity_cost + direction_penalty − attraction` with per-layer `layer_costs` and no congestion or history term ([router.rs](https://github.com/atomic14/KiCadRoutingTools/blob/main/rust_router/src/router.rs); [routing_config.py](https://raw.githubusercontent.com/drandyhaas/KiCadRoutingTools/main/py_router/routing_config.py)). The brief understates what KRT has: `analyze_frontier_blocking()` attributes a failed net's blocked frontier cells to routed nets, rips the top 1..3 blockers progressively, memoises `(net, blockers)`, and applies a soft ripped-corridor penalty (1.0 mm radius, 0.1 mm-equivalent) ([rip-up-reroute.md](https://raw.githubusercontent.com/drandyhaas/KiCadRoutingTools/main/docs/rip-up-reroute.md)); but nothing persists across nets or rounds.

The minimal retrofit is a cost term and an outer loop; A* and negotiation compose (Swartz/Betz/Rose: α = 1.5 directed search, 52× faster, "no measurable quality loss" ([Swartz et al. 1998](https://ece.iastate.edu/~zambreno/classes/cpre583/2006/documents/SwaBet98A.pdf)); VPR adds congestion to the backward cost only ([connection_router.tpp](https://github.com/verilog-to-routing/vtr-verilog-to-routing/blob/master/vpr/src/route/connection_router.tpp))). Because KiCad DRC grades output, use TritonRoute's violation-site form rather than VPR's overlap-then-negotiate: keep the single pass as iteration 1; add `acc_cost[layer][y][x]` (init 1.0); after the pass, run A* for each failed net with other nets' cells as soft cost, and bump `acc_cost += acc_fac·1` (or +10 with ×0.95 decay) on every occupied cell along that path and its frontier; rip every net occupying such a cell (VPR's "any overused node"), capped per net per iteration (`mazeEndIter`); reroute with `g += move_cost·acc_cost·(1 + pres_fac·occupied)`, `pres_fac` 0.5 growing ×1.3–2 per iteration; stop at zero opens or 5 stalls, doubling search boxes every 5 stalls. Plane layers keep capacity 1; model scarcity with KRT's `layer_costs` (2.5–4×, analogous to CUGR's `LARGE_NUM` on layer 0) plus a per-route length cap, with `acc_cost` pre-seeded near the plane net's vias. Expected iterations sit at the low end of the FPGA range (SPRoute 15–20; OrthoRoute's PCB PathFinder *expects* 15–25, unmeasured ([OrthoRoute](https://hub.allspice.io/AllSpiceMirrors/OrthoRoute/src/branch/main/orthoroute/algorithms/manhattan/unified_pathfinder.py))); no peer-reviewed convergence count exists for a PathFinder retrofit on a PCB grid.

**What this would mean for our tools.** (1) History term plus outer loop in kicad-route, seeded from `analyze_frontier_blocking()` — moderate cost (two arrays, one cost line in `router.rs`, a Python loop), highest payoff for bus opens. (2) Widen rip-up from "top ≤3 blockers" to "every net on the failed net's soft-cost path" with a per-net reroute cap — small change in existing machinery. (3) Plane multiplier plus length cap via `layer_costs` — configuration. (4) Freerouting cannot gain history without a fork; its usable levers are the fanout settings below and `-mp`, with the expectation that more passes will not move the plateau.

## 4. Escape and fanout: audit capacity, reserve one via site per trapped pad

Escape routing is a flow network: super-source to every pin, gaps between adjacent pads as edges with capacity `C = floor((p − d − s)/(w + s))` (diagonal `D = floor((√2·p − d − s)/(w + s))`), super-sink on the field boundary; max-flow bounds and guides the escape, and an escaped pad frees capacity on neighbouring edges ([Wang/Shi/Cheng ICCAD 2006](https://www.cecs.uci.edu/~papers/iccad06/papers/10C_3.pdf)). Yan & Wong corrected diagonal capacity (DAC 2009, DOI 10.1145/1629911.1630001; TCAD 2012, DOI 10.1109/TCAD.2011.2169258) ([HKBU](https://scholars.hkbu.edu.hk/en/publications/a-correct-network-flow-model-for-escape-routing/)). Transferable ordered/simultaneous-escape ideas: Ozdal & Wong's layer filling by largest planar subset (TCAD 2006, DOI 10.1109/TCAD.2005.857376) ([HKBU](https://scholars.hkbu.edu.hk/en/publications/algorithms-for-simultaneous-escape-routing-and-layer-assignment-o/)); B-Escape's dynamic ordering by trap cost with a routable region that shrinks as pins commit, routing all 14 industrial cases where Allegro routed 7 ([B-Escape slides](https://ispd.cc/ispd2026/slides/2010/2_05.pdf)); and NCER, PathFinder applied to PCB escape, which with Allegro covered 11/14 cases that each solved only 7 of ([ISQED 2010](https://www.isqed.org/English/Archives/2010/Technical_Sessions/123.html)).

Industry fanout is per-pad, via-terminated and decided *before* routing by a direction policy, not by a global router: dog-bone for pitch ≥ 0.5 mm, via-in-pad below; one trace per channel lets two BGA rows escape per layer (Xilinx XAPP157: "a minimum of eight PCB layers are required to route 10 signal rows") ([XAPP157](https://www.te.rl.ac.uk/esdg/cms-fed/xilinx-fpgas/virtex2/app_notes/xapp157_routing.pdf); [NexLogic](https://www.embedded.com/?p=4438466)). Altium's Fanout Control exposes In Only / Out Only / In Then Out / Alternating, BGA quadrant Away From Center, and Staggered Rows ([Altium](https://altium.com/documentation/altium-designer/pcb-routing-rule-fanout-control)); Eagle's `FANOUT` takes OUT/IN/ALTERNATE ([Fusion ECAD](https://help.autodesk.com/cloudhelp/ENU/Fusion-ECAD/files/ECD-CLI-F.htm)); Specctra "will always do the quadrant mode unless clearances prohibit it" ([Cadence forum](https://community.cadence.com/cadence_technology_forums/pcb-design/f/pcb-design/15363/fanout-in-specctra-autorouting)). No source gives a "toward the nearest board edge" rule; the universal rule is away from the package centre.

The open-source routers bracket the design space. TritonRoute's pin-access pre-pass enumerates K = 3 DRC-clean access points per pin with valid directions and a primary via, picks compatible patterns per row by DP, and reserves each unrouted net's preferred up-via by object cost during rip-up ([TritonRoute TCAD 2020](https://par.nsf.gov/servlets/purl/10171008); [FlexPA.h](https://raw.githubusercontent.com/The-OpenROAD-Project/OpenROAD/master/src/drt/src/pa/FlexPA.h)); the PAO paper reports failed pins dropping from thousands to zero and 2 DRCs on ispd18_test5 versus 755 for Dr. CU 2.0, the strongest evidence that static access analysis improves completion, albeit for standard cells ([PAO DAC 2020](https://vlsicad.ucsd.edu/Publications/Conferences/377/c377.pdf)). Freerouting's master runs `BatchFanout` before autorouting: components by descending SMD pin count, pins `outer_first` (alternative `surroundingsDensity`), each maze-routed "until the first via" with vias rejected closer than `min_escape_length_mm` = 2.5 or beyond `max_escape_length_mm` = 4.5, stopping after 3 identical passes because the maintainers saw 14 identical passes of pins ripping each other's escapes on a dense SMD carrier ([BatchFanout.java](https://github.com/freerouting/freerouting); [settings.md](https://github.com/freerouting/freerouting/blob/master/docs/settings.md)). `DirectPinRouting` routes same-layer connections with vias off before any escape, and the default chain `direct-first,fanout-retry,short-escape,open-escape,no-fanout` shows the maintainers do not regard fanout-first as universally better ([migrating_Eriks_improvements_part_2.md](https://github.com/freerouting/freerouting/blob/master/docs/migrating_Eriks_improvements_part_2.md)).

Worked numbers (w = s = 0.2): 2.54 mm-pitch connector pins with 1.6–1.7 mm pads leave ≈0.85–0.95 mm, exactly one track; 2.0 mm pitch with 1.2–1.4 mm pads leaves 0.6–0.8 mm, one track and marginal; 0402/0603 at 0.26 mm courtyard gap, zero. Every intra-block net that is not pad-to-adjacent-pad must leave along the ladder's free axis or by via, and the check is geometric: does drill + annular + 0.2 mm fit beside the pad. On plane layers any slot forces return current around it (Johnson: `L ≈ 5·D·ln(D/W)`, ≈0.9 nH for a 2 mm slot under a 0.2 mm trace ([Utah ECE 5320](https://my.eng.utah.edu/~cfurse/ece5320/lecture/L39/L39.pdf))), and crossing a split in the *power* plane is tolerable only if a solid GND plane remains under the signal ([Olney 2012](https://www.icd.com.au/articles/Plane_Jumpers_PCBDesign-Nov2012.pdf); [Riazi 2007](https://www.pcdandf.com/pcdesign/index.php/articles-by-subject/210-signal-integrity/3385-effects-of-plane-splits-on-high-speed-signals-part-1)). Since In1 (GND) references F.Cu and In2 (+3V3) references B.Cu, short tracks belong on +3V3 only, where no B.Cu signal crosses and away from the IMU/RF block; no source gives a maximum length, so that envelope is our inference.

**What this would mean for our tools.** (1) Freerouting, config only: `router.fanout.min_escape_length_mm` 2.5 → ≈0.6–0.7 (via radius + clearance + pad half-size for a 0.5 mm via), `max_escape_length_mm` ≈1.5, `pin_sorting_order = surroundingsDensity`, keep `direct-first`, read "escaped SMD pins (x%)" as the metric — the 2.5 mm default forbids vias inside a packed block outright. (2) In kicad-route, a static pre-pass: capacity-audit each block with `floor((gap − 0.2)/0.4)`, route direct pad-to-neighbour nets with vias off, then for each trapped pad enumerate via centres on-grid → half-grid → pad-aligned in a ring on the block's free side, pick compatible sites along the ladder by one-dimensional DP (via-to-via ≥ via_dia + 0.2 mm forces staggering), draw the stub, reserve the site as an obstacle for other nets; moderate cost, converts the dense multi-net problem into independent stubs. (3) Order blocks by B-Escape trap cost, most constrained first.

## 5. Benchmarks and evaluation: PCBench/PCBWorld give scale-comparable boards and a standard scorecard

Four usable KiCad-centric corpora exist. PCBench (MIT repo; README says 164 boards, the clone holds 1,183, 126 of them 4-layer, with original human routing in `final.json`; 605 boards record no source license) ships `Baselines/Results_all.csv` with Success/wirelength/vias/runtime: Freerouting 860/1,185, PcbRouter 515, RL-MCTS 2 ([PCBench](https://github.com/PCBench/PCBench)); Freerouting uses it nightly with KiCad DRC on `raw.kicad_pcb` as arbiter ([scripts/pcbench/README.md](https://github.com/freerouting/freerouting/blob/master/scripts/pcbench/README.md)). PCBWorld-Bench (LG AI Research, arXiv 2607.05915; BSD-3 code, GPLv3 engine) curates 679 DRC-clean KiCad 9 boards from PCBench; D3-C (292 boards, 6–451 nets, 101–2,103 pads) is the only public set at our scale, and Table 3 gives reference points on D3-A/B: Freerouting Clean Pass 0.80/0.78, Routability 0.91/1.00; KiCadRoutingTools CP 0.74/0.20, Routability 0.94/0.86 ([PCBWorld](https://arxiv.org/pdf/2607.05915); [README](https://github.com/LGAI-Research/PCBWorld)). The DAC-2020 PCB-Benchmarks are 11 routed boards (8–61 footprints, 15–99 nets, no license), matching PCB1–11 of the UCSD suite; PCB12–14 are not public ([DAC-2020](https://github.com/DAC-2020-Submission-1703/PCB-Benchmarks); [arXiv 2210.14259](https://arxiv.org/pdf/2210.14259)). Cypress ships 20 placement-only Bookshelf benchmarks ([Cypress](https://github.com/NVlabs/Cypress)). ISPD-style PCB sets, a UCSD/TILOS PCB benchmark, Kaggle/HF board datasets, OmniRouting's 1,681 designs and the Yan/Wong escape suites could not be verified as public (UNVERIFIED).

The IC contests define the vocabulary: edge overflow `max(0, demand − capacity)` with capacity in pitches (`capacity/(MinWireWidth + MinWireSpacing)`), TOF/MOF primary, wirelength × (1 + 0.04·log2(t/t_median), ±0.1) secondary ([ISPD 2008](https://www.ispd.cc/contests/08/ispd08rc.html); [ISPD 2011](https://www.ispd.cc/contests/11/ispd2011_contest.html)); GLARE's ACE(x) = mean congestion of the top x% edges, PWC = mean of ACE(0.5, 1, 2, 5), RC = max(100, PWC), sHPWL = HPWL·(1 + 0.03·(RC − 100)) ([US8584070](https://patents.google.com/patent/US8584070); [RePlAce](https://vlsicad.ucsd.edu/Publications/Journals/j126.pdf)); ISPD 2018/19 weights shorts and spacing 500, vias 2 (4/2 single/multi-cut in 2019), wirelength 0.5, any open net a veto ([ISPD 2018](https://www.ispd.cc/contests/18/metric_and_ranking.pdf); [ISPD 2019](https://www.ispd.cc/contests/19/metrics_and_ranking.pdf)). PCB papers use a smaller set: "routability" almost always means a *connection*-level ratio (Cypress pin pairs; PCBWorld connections; DeepPCB airwires, mean 95.6% over 32k self-reported jobs with no DRC data ([DeepPCB](https://deeppcb.ai/pcb-autorouter-benchmark-2026/))), while UCSD reports net-level "#DRVs + #unrouted nets." Freerouting's score `max(0, 1000 − W1·o1 − W2·o2 − 25·N_viol/D − 300·ΣL_um/(1000·D))`, `D = max(1, pins × signal_layers)`, is the one existing cross-board normaliser ([scoring.md](https://github.com/freerouting/freerouting/blob/master/docs/scoring.md)); its `result_json` manifest exposes `connections{maximum_count, incomplete_count}`, `clearance_violations{router_introduced_count}` and `fanout{escaped_count}` ([RoutingResultManifest.java](https://github.com/freerouting/freerouting/blob/master/src/main/java/app/freerouting/core/results/RoutingResultManifest.java)). KiCad 10's `kicad-cli pcb drc --format json` emits `violations[]`, `unconnected_items[]`, `schematic_parity[]`, each `{type, description, severity, items[{uuid, description, pos}]}`, documented only in `rc_json_schema.h`; one `unconnected_items` entry equals one unrealised ratsnest edge ([KiCad CLI](https://docs.kicad.org/10.0/en/cli/cli.html); [rc_json_schema.h](https://docs.kicad.org/doxygen/rc__json__schema_8h_source.html); [drc_test_provider_connectivity.cpp](https://docs.kicad.org/doxygen/drc__test__provider__connectivity_8cpp_source.html)).

| Metric | Definition | Precedent |
|---|---|---|
| Completion (connections) | routed / total ratsnest edges | PCBWorld, Cypress, DeepPCB, Freerouting `f` |
| Open nets / open connections | nets with ≥1 `unconnected_items`; entry count | UCSD, ISPD 2018/19 veto |
| Clean Pass | completion = 1 and zero error-level DRVs | PCBWorld CP, PCBench Success |
| DRC by class | open / short (`shorting_items`, `tracks_crossing`) / spacing (`clearance`, `hole_clearance`, `copper_edge_clearance`) / geometry / dangling | ISPD 2018, OpenLane |
| Vias | total, per connection, by type | DeepPCB, Freerouting, ISPD 2019 |
| Track length, ratio to FLUTE/MST bound | Σ length / Σ RSMT | FLUTE, STAIRoute, Freerouting `L_min` |
| Runtime | wall-clock, ±0.1-capped log2 factor | ISPD 2008/2018 |
| Placement proxy | RUDY peak/P90; TOF/MOF/ACE on 0.4 mm g-cells | ISPD 2011, DAC 2012 (IC only) |

**What this would mean for our tools.** (1) Report "203/235 nets" alongside the connection-level ratio from `unconnected_items` on a `--severity-all --refill-zones` run, plus Clean Pass and DRC-by-class, so a future 235/235 with residual clearance errors is distinguishable from clean — a small JSON extractor. (2) Adopt PCBWorld's metrics and Freerouting's `D` normaliser so numbers land next to Table 3 and `Results_all.csv`. (3) Build a regression corpus from PCBench's 126 4-layer boards (strip routing with `clean.py`), run both backends, and track ACE/RUDY only internally since no PCB paper publishes them.
