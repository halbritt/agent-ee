# fome-mc material in agent-ee

## Rights

The owner of agent-ee, halbritt, also owns fome-mc
(<https://github.com/halbritt/fome-mc>). The owner holds the rights to both
repositories. On 2026-10-18 the owner decided that captured fome-mc reference
sheets are committed to agent-ee as fixtures. The decision is recorded in
[`docs/decisions.md`](../../docs/decisions.md), under "fome-mc reference sheets
are committed as fixtures".

This notice records that decision and where the material came from. It grants no
licence beyond the owner's decision. The MIT proposal in [`LICENSE`](../../LICENSE)
does not cover these files. [`docs/file-origins.json`](../../docs/file-origins.json)
classifies them under origin `T16`, not as agent-ee material.

## Rules for fome-mc fixtures

Every fome-mc fixture in agent-ee follows these rules:

1. Capture uses the offline Git path. Files are read only from a local fome-mc
   repository's object store at one full, pinned commit. There is no network,
   no remote transport and no fetch. Working-tree files are never read, so a
   dirty or moved checkout cannot leak into a capture. Nothing is ever written to
   fome-mc. Files are never copied by hand.
2. Every captured file records its fome-mc commit and SHA-256. `block.json`
   records `source.commit` and `files`. `inventory-report.json` records
   `source_files`, which gives each source path's SHA-256, its Git blob id and
   whether a block copies it.
3. Only blocks that the generator consumes are committed, with the files that
   those entries name. Planning documents such as `docs/DESIGN.md` and
   `docs/BLOCK_LIBRARY.md` are not blocks and are never copied. Requirements cite
   them in the pinned-external form: repository, commit, path, Git blob id and
   SHA-256. `source_files` lists them with `captured: false`.
4. Each added path has a `docs/file-origins.json` rule with origin `T16`.
